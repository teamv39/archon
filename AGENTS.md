# AGENTS.md — инструкция для агентных моделей

Этот файл — вход для любой LLM, работающей с репозиторием Archon.
Прочитай его первым, прежде чем трогать код или доки.

## Что такое Archon

Archon — enterprise-платформа docs-as-code и AI-native Source of Truth (Managed SaaS). Миссия — **Zero Drift**:
документация не расходится с кодом, а AI-агенты и инженеры получают проверенную архитектуру.

Интерфейсы взаимодействия: 4 ключевых канала — **MCP-сервер** (для IDE AI-агентов), **веб-портал** (для людей), **Git Sync / PR-бот** (двусторонняя синхронизация доков и гейты), **Public API** (для CI/CD и скриптов) + вспомогательный **чат-бот**. Внутри — 17 логических модулей (фабрика), включая генератор артефактов `export`. Подробно —
`docs/architecture/product-overview.md`.

## Ключевые договорённости

- **17 модулей — логика, не сервисы.** MVP собирается из 2-3 сборочных
  единиц (OQ-8). Модуль != сервис.
- **Людей к модулям не привязываем** (ADR-0004, решение 4). В модуле
  поле "Компетенция" опционально, владельца нет.
- **Продуктовый срез (5 блоков)** и **технический срез (7 слоёв)** —
  два взгляда на одни и те же 17 модулей. Для рассказа — блоками.
- **Блокеры для кода:** OQ-8 (топология).
  OQ-1 закрыт ADR-0002, OQ-2 и OQ-5 закрыты ADR-0003. Код, зависящий от открытого OQ, не пишем; сначала ADR.
- **Декомпозиция принята** (ADR-0004, аддендум ADR-0006). Не перепридумывай модули без ADR.

## Как работать

1. Прочитай `AGENTS.md` (этот файл) и `docs/INDEX.md`.
2. Найди задачу в GitHub Issues/Projects или уточни у пользователя.
   - Готовые к работе задачи команды:
     ```bash
     python3 scripts/tasks.py --ready
     ```
   - Задачи конкретного человека (фильтр по имени или логину):
     ```bash
     python3 scripts/tasks.py --assignee паша   # или денис, миша, макс
     ```
   - Прямой вызов через GitHub CLI:
     ```bash
     gh project item-list 2 --owner teamv39 --format json
     gh issue list --state open --limit 30
     ```
3. Перед правкой — прочитай затрагиваемые файлы (Read, не угадывай).
4. Правь доки и код в одном PR/коммите, если меняешь поведение.
5. Архитектурные решения — только через ADR (`docs/adr/TEMPLATE.md`).
   Споры — в `open-questions.md`, не в файлах модулей.
6. Один модуль = один файл в `docs/architecture/modules/` по
   `TEMPLATE.md`. Модуль без строки в `modules/README.md` не существует.

## Стиль

- Язык доков — русский, стиль — коротко и по-человечески.
- Без эмодзи, без пафоса, без декоративного юникода.
- Диаграммы — `mermaid` (flowchart). ASCII-бокс только для деревьев
  директорий. Проверяй рендер.
- Проверяй отсутствие CJK-артефактов после правки на русском
  (`grep -P '[\x{4e00}-\x{9fff}]'`).
- Сохраняй бренды в цитатах/коде/путях как есть.

## Git

- Сейчас база строится — пуш в `main` разрешён (решение лида).
  Когда скажут "теперь через PR" — включится branch protection.
- Ветки: `feature/<id>-kebab` от `main`. Пока без `develop`.
- Коммиты: `ARCH-123: что сделано` или краткий префикс типа
  `Docs:` / `Research:` / `Architecture:` если вне трекера.
- Перед пушем: `git status`, `git diff --stat`, проверка ссылок.

## Что не делать

- Не заводи `develop`/`module/*` ветки без просьбы.
- Не назначай задачу на двоих (один assignee, второй — reviewer).
- Не храни решения в чате — если нет в GitHub/docs, этого нет.
- Не расширяй скоуп молча. Нашёл проблему шире задачи — скажи одной
  фразой, продолжай в рамках скоупа.
- Не генерируй код, зависящий от OQ-2/8, без пометки `spike:`.

## Чек-лист перед PR/пушем

- [ ] Дока обновлена вместе с кодом (если менялась архитектура — ADR/OQ)
- [ ] Ссылки в `docs/INDEX.md` и `research/README.md` обновлены (если новый док)
- [ ] Mermaid рендерится, CJK-артефактов нет
- [ ] Коммит маленький, сообщение понятное
