# 0001. Docs-as-Code подход для технической документации

Дата: 2026-08-29

## Статус

Accepted

## Контекст

Проект Archon сам по себе решает проблему устаревания документации. Нам нужно выбрать подход к ведению собственной документации, который будет:
- Референсным примером для будущих пользователей продукта
- Эффективным для распределенной команды из 4 человек
- Масштабируемым при росте проекта

Текущая практика в индустрии: Confluence как основное хранилище документации. Проблемы:
- Документация быстро устаревает относительно кода
- Нет связи между кодом и документацией
- Сложно делать code review документации
- История изменений не прозрачна

## Решение

Используем Docs-as-Code подход:
- Вся техническая документация в Git в формате Markdown
- Структура `/docs` с разделением по типам документов
- ADR (Architecture Decision Records) для фиксации архитектурных решений
- Изменения в документации ревьюятся вместе с кодом в PR
- Confluence только для бизнес-контекста и cross-team collaboration

## Альтернативы

**Confluence как source of truth:**
- Проще для нетехнических ролей
- Привычный инструмент в enterprise
- Отклонили: противоречит идеологии Archon, сложно поддерживать синхронизацию с кодом

**Wiki в GitHub/GitLab:**
- Интегрирован в платформу
- Отклонили: отдельная история изменений, нет атомарности с кодом в PR

**Отдельный репозиторий для документации:**
- Чистое разделение кода и документации
- Отклонили: усложняет синхронизацию, теряется контекст изменений

## Последствия

### Плюсы
- Документация всегда в sync с кодом (меняется в том же PR)
- Прозрачная история изменений через Git
- Code review для документации
- Автоматизация генерации документации из кода
- Мы сами используем то, что проповедуем пользователям

### Минусы
- Барьер входа для нетехнических ролей (нужен Git)
- Сложнее делать rich-форматирование (по сравнению с Confluence)
- Нужна дисциплина команды для поддержания актуальности

### Риски
- Команда может игнорировать обновление документации в PR
- Митигация: включить проверку документации в code review чеклист
