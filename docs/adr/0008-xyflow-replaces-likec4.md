# 0008. @xyflow/react и elkjs заменяют LikeC4

Дата: 2026-11-07

## Статус

Accepted

Принято на созвоне команды портала 2026-11-07. Частично заменяет [ADR-0002](0002-archmap-fate.md) в части LikeC4 (визуализация и генерация DSL), уточняет состав `archon-portal` в [ADR-0007](0007-saas-process-topology-and-packaging.md). Подробное обоснование и архитектура холста: [RFC Architecture Canvas on React Flow](../architecture/rfc-architecture-canvas-react-flow.md).

## Контекст

В ADR-0002 из прототипа `archmap` в ядро были перенесены идеи, в том числе иерархия C1-C3 в LikeC4 DSL. В портале для карты архитектуры выбрана библиотека `@likec4/diagrams`, а модуль `export` должен был генерировать `.c4` файлы.

В ходе спринтов 1-2 выявились ограничения (подробно в RFC, раздел 2): закрытый рендерер узлов не позволяет реализовать макеты Figma и индикаторы Zero Drift, ghost-связи плохо ложатся на валидный DSL, нужен лишний слой трансляции графа в DSL и компиляции, есть риски совместимости с React 18/19 и размера бандла.

## Решение

1. Для интерактивной карты архитектуры (`/architecture`) и виджета в паспорте сервиса используем **`@xyflow/react` (React Flow v12) + `elkjs`**. Продуктовый слой (кастомные узлы и ребра, навигация по уровням C4, индикаторы дрейфа) реализуем в портале.
2. **LikeC4 полностью исключается** из стека: ни `@likec4/diagrams`, ни `@likec4/core`, ни `.c4`/DSL в конвейере портала.
3. Контракт BFF `/api/diagrams/c4` отдаёт структурированный JSON `{ nodes, edges }`, собранный из графа знаний. Расчёт координат выполняет клиент (`elkjs`).
4. Модуль `export` не генерирует LikeC4 DSL. Граф экспортируется как JSON-граф (тот же формат, что у BFF); Structurizr DSL остаётся возможным форматом экспорта. Задача ARCH-37 переформулируется: «Транслятор графа модели в JSON-граф для xyflow и экспорта».
5. Архивный прототип `archmap` (`docs/architecture/prototypes/archmap_dump/`, включая `json_to_likec4.py`) остаётся как Reference Examples по ADR-0002 и не развивается.

## Альтернативы

### Вариант 1: Оставить LikeC4
**Плюсы:** готовая раскладка и тулчейн.
**Минусы:** закрытый рендерер, невозможность реализовать макеты и статусы дрейфа, лишний слой DSL на бэкенде.
**Почему не выбрали:** не позволяет реализовать ключевую ценность витрины (Zero Drift на карте).

### Вариант 2: Гибрид (xyflow для карты, LikeC4 DSL для экспорта)
**Плюсы:** сохраняется возможность отдавать `.c4` в репозитории клиентов.
**Минусы:** поддержка двух форматов и генератора DSL ради экспорта, которого сейчас никто не запрашивал.
**Почему не выбрали:** команда решила полностью отказаться от LikeC4. Если появится спрос на экспорт в C4-формат, будем добавлять Structurizr DSL отдельным решением.

## Последствия

**Плюсы:**
- Полный контроль над рендерингом узлов и ребер (бейджи дрейфа, ghost-связи, Tier), единый UI-kit с остальным порталом.
- BFF без DSL-компилятора: чистый JSON REST API.
- Меньше зависимостей и рисков совместимости.

**Минусы:**
- Раскладку и навигацию по уровням C4 пишем сами (`elkjs`, оценка в RFC: 1-2 дня на PoC).
- Нужно переработать документацию и задачи, ссылающиеся на LikeC4 (выполнено вместе с этим ADR).

**Влияние на задачи:**
- ARCH-42 (карта в портале): реализуется на `@xyflow/react`, PR #34 в `archon-portal`.
- ARCH-46 (BFF): контракт `/api/diagrams/c4` отдаёт JSON `{ nodes, edges }`.
- ARCH-37 (export): транслятор в JSON-граф вместо LikeC4 DSL.
- ARCH-57 (обсуждение RFC): закрыта этим ADR.
