Автор: AI-ассистент на основе продуктовой документации, competitive analysis и рыночных данных.

## 1. Оценка ценности каждой функции

### Матрица ценности

| Функция | Бизнес-ценность | Частота использования | Кто использует | Уникальность на рынке |
| :--- | :--- | :--- | :--- | :--- |
| **Drift detection** (доки vs код) | Очень высокая | Ежедневно (автоматически) | Архитектор, тимлид | Уникальна (Swimm — только сниппеты) |
| **PR-бот / гейт** | Высокая | Каждый PR (автоматически) | Разработчик | Ни один IDP не даёт из коробки |
| **Граф знаний (model)** | Высокая | Фоновый процесс | Система (все фичи зависят) | Частично (Port "Context Lake") |
| **Impact analysis** ("кто зависит от X") | Высокая | 2-5 раз/неделю | Архитектор, SRE | Частично (IDP каталоги) |
| **Портал (карта + каталог)** | Средняя | Ежедневно | Все роли | Есть у всех конкурентов |
| **Policies (архитектурные правила)** | Средняя | Ежедневно (автоматически) | Архитектор | Есть у Port/OpsLevel (scorecards) |
| **Assurance (lifecycle находки)** | Средняя | Несколько раз/неделю | Архитектор, тимлид | Частично у OpsLevel (campaigns) |
| **Чат-бот (RAG по графу)** | Средняя | 3-10 раз/день | Разработчик, новичок | Частично (Rovo, Port AI) |
| **Экспорт (отчёт на дату)** | Низкая-средняя | 1-4 раза/квартал | CISO, аудитор, PM | Есть у OpsLevel |
| **Карта/диаграммы (C4)** | Средняя | 2-3 раза/неделю | Архитектор | Есть у Structurizr/IcePanel |

### Что реально ценно (по убыванию)

**Tier 1 — "за это заплатят":**
1. **Drift detection с доказательством из кода** — главный нарратив. "Документ Х утверждает Y, а в коде Z. Вот строка." Ни один конкурент этого не делает на уровне архитектуры.
2. **PR-бот с гейтом** — автоматическая проверка при каждом PR, блокировка мержа при расхождении. Встроен в workflow разработчика, не требует ручных действий.

**Tier 2 — "усиливает ценность, но не продаёт сам по себе":**
3. **Impact analysis** — "если я поменяю этот контракт, кто сломается?" Ценно, но аналоги есть (каталоги IDP).
4. **Assurance (lifecycle находки)** — "риск принят CTO 2026-01-15, обоснование: миграция в Q2". Отличает от галочки-чеклиста у конкурентов.

**Tier 3 — "необходимо для полноты, но не killer feature":**
5. **Портал** — ожидание рынка, без портала нечего показать. Но это table stakes.
6. **Чат-бот** — удобство, не уникальность.
7. **Экспорт** — нужен для enterprise продаж (compliance), но 4 раза в квартал.

## 2. Частота использования и вовлечённость

### Ожидаемая модель использования

```
Ежедневно (автоматически, без участия человека):
  - Drift detection: фоновый прогон по расписанию
  - Policies: автоматическая проверка правил
  - PR-бот: срабатывает на каждый PR
  - Граф: обновляется при каждом прогоне

Ежедневно (пользователь):
  - Портал: просмотр инбокса (2-5 мин)
  - Чат-бот: 3-10 вопросов в день (если есть)

Еженедельно:
  - Impact analysis: 2-5 запросов
  - Assurance: разбор находок, принятие решений
  - Карта/диаграммы: просмотр при обсуждениях

Ежеквартально:
  - Экспорт: 1-4 отчёта
  - Зрелость: обзор динамики
```

### Риск низкой вовлечённости

**Проблема:** если drift detection находит мало расхождений (код и доки совпадают), система становится "тихой". Пользователь перестаёт заходить.

**Митигация:**
- Policies дают постоянный поток находок (структурные правила нарушаются чаще, чем drift)
- Онбординг новичков — постоянный use case
- Зрелость/метрики как daily dashboard для тимлида

## 3. Экономика: сколько экономит vs сколько стоит

### Стоимость проблемы (что экономим клиенту)

**Потери от устаревшей документации (industry benchmarks):**

Данные из отраслевых исследований (GitHub, Stack Overflow, Stripe):
- Разработчик тратит 3-5 часов/неделю на поиск и верификацию информации
- 40-60% внутренней документации устаревает в течение 6 месяцев
- Средняя стоимость инцидента из-за неактуальной документации (неправильное понимание зависимостей): 10K-50K USD
- Onboarding нового инженера: 3-6 месяцев до полной продуктивности; с актуальными доками — 1-3 месяца

**Расчёт для типичной команды (50 инженеров, 30 сервисов):**

| Статья экономии | Расчёт | Экономия/год |
| :--- | :--- | :--- |
| Время на верификацию доков | 50 чел * 2 ч/нед * 48 нед * $75/ч | ~$360,000 |
| Сокращение инцидентов (1-2 предотвращённых/год) | 1.5 * $30,000 | ~$45,000 |
| Ускорение онбординга (5 новичков/год * 1 месяц экономии) | 5 * $12,000 | ~$60,000 |
| Время архитектора на ручные ревью | 2 чел * 5 ч/нед * 48 нед * $100/ч | ~$48,000 |
| **Итого потенциальная экономия** | | **~$513,000/год** |

Реалистичная экономия Archon — 20-40% от потенциала (не все проблемы решаются инструментом): **$100K-200K/год**.

### Стоимость Archon (наши затраты)

**Стоимость владения для клиента (self-hosted):**

| Статья | Стоимость |
| :--- | :--- |
| Инфраструктура (VM/контейнер, PostgreSQL) | $200-500/мес |
| LLM API (interpret + drift) | $500-2,000/мес (зависит от объёма, модели) |
| Лицензия Archon (наш revenue) | ? (см. pricing ниже) |
| Время DevOps на поддержку | 2-4 ч/мес |

**LLM — самая большая переменная.** При 30 сервисах и ежедневном прогоне:
- GPT-4 class: ~$1,500/мес (много токенов на Confluence + код)
- Llama/Mistral local: ~$300/мес (GPU) + меньше качество
- Гибрид: ~$800/мес

Задача Миши (M1) — посчитать точно.

### Ценообразование конкурентов (верифицировано)

| Продукт | Модель | Цена | Что получаешь |
| :--- | :--- | :--- | :--- |
| **Port** | Per-seat/month, SaaS | Free (до 15 чел), $30 (Basic, до 50), $40 (Standard, до 200), Custom (Enterprise) | Каталог + scorecards + AI agents, NO drift |
| **OpsLevel** | Per-developer, SaaS | Custom pricing (не публичная), контакт sales | Каталог + checks + campaigns, NO drift |
| **Swimm** | Custom (services) | Не публикуется, "Book a call" | Docs drift на уровне сниппетов, NO архитектурный граф |
| **Backstage** | OSS (бесплатно) | $0 + команда на поддержку (1-3 FTE) | Каталог-фреймворк, NO drift |
| **Structurizr** | Flat license | ~$200/мес (cloud), $3,000/год (on-prem) | C4-диаграммы, NO drift, NO каталог |

**Вывод по ценообразованию:**
- $30-40/seat/month — нижняя граница рынка IDP (Port)
- Enterprise custom pricing скрывает реальные цифры ($50-100/seat/month — типичный диапазон для OpsLevel/Cortex)
- Backstage "бесплатен", но стоит 1-3 FTE ($150K-450K/год) на поддержку

**Наш потенциальный прайс-поинт:**
- Open-core: базовый CLI бесплатно (extract + model + drift report)
- Team: $25-35/seat/month (портал, PR-бот, assurance, policies)
- Enterprise: $50-80/seat/month (SSO, RBAC, audit, Confluence/Jira адаптеры, SLA)
- Self-hosted premium: flat license $2,000-5,000/month

При 50 инженерах: $1,250-1,750/мес (Team) — ROI 5-10x от экономии $100K-200K/год.

## 4. Продуктовые и бизнес-дырки

### Критические дырки (блокируют growth)

**D1. Нет механизма "быстрой победы" (Time-to-Value)**

Проблема: чтобы Archon начал приносить пользу, нужно:
1. Развернуть систему
2. Подключить репозитории
3. Дождаться прогона extract + interpret
4. Дождаться drift detection
5. Разобраться в портале

Это может занять часы/дни. Конкуренты (Port) дают результат за 15 минут (подключил GitHub — видишь каталог).

Решение: CLI-first помогает (`archon analyze ./repo` → stdout с находками за 5 минут), но нужен **onboarding path**: первый drift-результат должен появиться максимально быстро.

**D2. Нет доказательства качества drift detection**

Проблема: главная фича (drift) зависит от LLM. Клиент спросит:
- Какой % ложных срабатываний (false positive rate)?
- Какой % пропусков (false negative rate)?
- Как Archon отличается от "просто спросить ChatGPT"?

Пока нет бенчмарка и нет метрик качества. Без этого продавать enterprise сложно.

Решение: нужен benchmark dataset (10-20 реальных расхождений + 10-20 совпадений) и метрики precision/recall. Задача для Миши.

**D3. Зависимость от LLM как single point of failure**

Проблема: если LLM не работает (API упал, air-gapped без GPU) — модули interpret и drift не работают. Это половина ценности.

Решение: graceful degradation. extract (AST) работает без LLM. Drift должен иметь "лёгкий режим" (сравнение структурных фактов без семантики). Policies работают без LLM вообще.

**D4. Нет стратегии adoption (Land & Expand)**

Проблема: кто конкретно внутри компании-клиента будет champion'ом Archon? Нет внятного ответа.
- Архитектор? — может не иметь бюджета.
- VP of Engineering? — далёк от daily workflow.
- Platform team? — им проще Backstage.

Решение: нужен playbook "кто покупает и почему". Гипотеза: архитектор или Head of Architecture, которому нужно доказать, что документация актуальна (compliance, аудит, регулятор).

### Серьёзные дырки (замедляют рост)

**D5. Нет retention loop**

Проблема: Archon — система типа "поставил и забыл". Если drift починили — система молчит. Нет причины возвращаться каждый день.

Решение:
- Weekly digest: "на этой неделе обнаружено X, закрыто Y, зрелость +Z%"
- Trend dashboard: динамика дрейфа по командам/сервисам
- Gamification: "у команды Payments 95% актуальность документации — лучший результат"

**D6. Непонятная граница с Backstage**

Проблема: если у клиента уже есть Backstage, зачем ему Archon? Ответ "мы слой знаний поверх" не очевиден без демо.

Решение:
- Интеграция: Archon читает catalog-info.yaml Backstage и обогащает граф
- Конкретный нарратив: "Backstage показывает что есть, Archon показывает что врёт"
- Плагин для Backstage как точка входа (фаза 2+)

**D7. Open-core стратегия не определена**

Проблема: если CLI бесплатный и уже показывает drift — зачем платить за Team?

Решение: бесплатный CLI = single repo, no history, stdout only. Платный = multi-repo, resolve, портал, PR-бот, assurance, history, API. Но граница должна быть чёткой и не обижать community.

**D8. Нет истории успеха (social proof)**

Проблема: enterprise не купит без case study. У нас нет ни одного пользователя.

Решение: первый пилот на знакомых/из интервью. Запись результата как case study. Публичный demo-репозиторий с заранее расставленными drift-проблемами.

### Продуктовые пробелы (не блокируют, но ослабляют)

**D9. Нет версионирования графа (history)**

"Покажи мне архитектуру на 2026-01-01" — пока нельзя. Для аудита критично.

**D10. Нет multi-tenancy**

Один инстанс = одна компания. Для SaaS (OQ-18) это блокер.

**D11. Нет notification system**

Drift обнаружен — кого уведомить? Портал показывает, но push-нотификации (email, Slack, webhook) не описаны как отдельная фича.

**D12. Нет self-service onboarding**

"Я хочу добавить свой репозиторий в Archon" — workflow не описан. Кто может это сделать? Любой разработчик или только admin?

## 5. Unit-экономика и маржинальность

### Себестоимость одного клиента (self-hosted)

| Статья | Стоимость для нас | Примечание |
| :--- | :--- | :--- |
| Поддержка (support) | $500-1,000/мес | 1 инженер на 10-20 клиентов |
| Инфраструктура (если SaaS) | $500-2,000/мес | GPU для LLM, PostgreSQL, storage |
| Разработка (R&D) | распределённая | 4 FTE = ~$40K-60K/мес total |

**Self-hosted модель (Team, 50 seats):**
- Revenue: $1,500/мес ($30/seat)
- COGS: ~$200/мес (support доля)
- Gross margin: ~87%

**SaaS модель (если будет):**
- Revenue: $2,000/мес ($40/seat)
- COGS: ~$1,500/мес (infra + LLM + support)
- Gross margin: ~25% (плохо!)

Вывод: **self-hosted модель значительно маржинальнее.** LLM-затраты перекладываются на клиента. Это подтверждает решение ADR-0005 (self-hosted first).

## 6. Рыночный контекст

### Конкуренты двигаются в сторону AI

Port уже добавил "AI Agents", "Context Lake" и "AI management".
OpsLevel добавил "Maintenance Agent" и "Context Layer (MCP)".
Swimm переключился на "Agentic Development Context Layer".

**Тренд рынка:** IDP эволюционируют от каталогов к AI-платформам. Archon должен позиционироваться не как "ещё один IDP с AI", а как **специализированный движок drift detection**, который интегрируется с любым IDP.

### Ценовой потолок

Port Free (15 seats) + Backstage (OSS) создают ценовой пол. Enterprise-клиенты платят $50-100/seat, но ожидают зрелый продукт с SSO, RBAC, SLA.

Archon на старте не может конкурировать по полноте с Port/OpsLevel. Но может побить их в нише: **"мы находим то, что они не видят" (drift) + "мы работаем в вашем контуре" (self-hosted)**.

## 7. Рекомендации

### Приоритизация по ROI

1. **Drift detection + PR-бот** — строить первыми, демонстрировать первыми. Это и killer feature, и единственное, что нет у конкурентов.

2. **CLI с быстрым результатом** — `archon analyze ./repo` должен давать находки за < 5 минут. Это time-to-value и land strategy.

3. **Benchmark качества drift** — без precision/recall продавать enterprise невозможно. Начать собирать dataset сейчас.

4. **Портал — минимальный** — не гнаться за Port/Backstage по полноте каталога. Фокус: инбокс находок + карта + доказательства.

5. **Retention loop** — weekly digest, trend dashboard с первой версии портала.

### Что НЕ делать

- Не строить полноценный каталог (table stakes, не дифференциатор)
- Не конкурировать с Backstage как фреймворк
- Не начинать с SaaS (маржинальность плохая из-за LLM-затрат)
- Не делать чат-бот в MVP (nice-to-have, не продаёт)

## Открытые вопросы для интервью

На основе этого анализа, добавить в гайд интервью:

1. Как часто ваша документация не совпадает с реальным кодом? (оценка масштаба проблемы)
2. Сколько времени в неделю уходит на верификацию актуальности доков? (валидация экономики)
3. Был ли инцидент из-за неактуальной документации? Сколько стоил? (ROI proof)
4. Кто в вашей компании отвечает за актуальность доков? (champion identification)
5. Self-hosted обязателен или cloud допустим? (OQ-18 validation)
6. Готовы ли платить $25-40/seat/month за инструмент, который автоматически находит расхождения? (WTP validation)
7. Есть ли у вас Backstage/Port/OpsLevel? Что не устраивает? (competitive positioning)
8. Как вы сейчас блокируете мерж PR без обновления доков? Руками? (PR-бот validation)
