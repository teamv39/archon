# Шпаргалка для презентации Archon

## 30 секунд

Archon — платформа для **Zero Drift** и **AI-native Source of Truth**. Она сверяет документацию с реальным кодом, блокирует PR при расхождениях, сама поддерживает актуальные docs-as-code файлы (`AGENTS.md`) и отдаёт проверенный контекст AI-агентам (Cursor, Copilot) через протокол MCP. Такого сквозного решения сейчас нет на рынке.

## Что видит пользователь (интерфейсы взаимодействия)

Внутри 17 модулей («фабрика»), а снаружи — ключевые интерфейсы взаимодействия:

- **MCP-сервер и Docs-as-Code** — AI-агенты в IDE (Cursor, Copilot) запрашивают контекст напрямую из графа Archon, а система сама коммитит актуальные файлы контекста (`AGENTS.md`).
- **Портал (веб)** — интерактивные C4-диаграммы, каталог сервисов, инбокс проблем ("здесь код разошелся с документом"), оценка зрелости.
- **Бот в Git** — комментирует PR: "Ты изменил код, обнови документ `docs/payments.md`". Можно настроить блокировку мержа.
- **Public API (REST / GraphQL)** — программный доступ для CI/CD quality gates и внешней автоматизации.
- **Чат-бот** — отвечает на вопросы типа "кто владелец сервиса платежей?" со ссылкой на код и провенанс.
- **Экспорт артефактов** — модуль `export` компилирует docs-as-code и выгружает отчёты на дату для аудита (PDF/JSON).

Всё остальное — невидимая "фабрика", которая это делает. Подробнее — `architecture/product-overview.md`.

## 5 блоков (как объяснять устройство)

Для презентации группируй 17 модулей по близости к пользователю:

| Блок | Что делает | Пример |
| :--- | :--- | :--- |
| Витрина | Показывает результат и отдаёт контекст | Портал, бот в Git, MCP-сервер, чат-бот, генератор экспорт |
| Решение | Следит за статусом каждой проблемы | "Обнаружена → исправлена / риск принят / ложная тревога" |
| Мозг | Строит граф из кода и документов, ищет проблемы | Граф связей, поиск противоречий, склейка сервисов |
| Фабрика | Читает код, документы, разбирается в конфликтах | Парсеры кода (AST), LLM для смысла, сведение фактов |
| Фундамент | Очереди, права, аудит, изоляция клиентов | Изоляция тенантов, планирование задач, бюджеты LLM |

**Для MVP:** витрина = портал + бот в Git + MCP-сервер, главная ценность — "документы не врут, а AI-агенты получают проверенную архитектуру".

## Как это работает (если спросят технические детали)

Короткий ответ: система читает код и манифесты через парсеры → строит граф связей (Knowledge Graph) → сверяет с документами → генерирует контекст для AI и показывает расхождения инженерам.

Полная схема потока данных в `modules/README.md`.

## Что изменилось в последней версии декомпозиции (ADR-0004 + ADR-0006)

Было 10 модулей с буквами → стало 17 плоских модулей. Ключевые изменения:
- MCP-сервер включен в витрину для прямого снабжения AI-агентов контекстом.
- Отдельный модуль для разрешения конфликтов между источниками (`reconcile`).
- Разделили "что анализировать" (`registry`) и "как подключиться к источникам" (`sources`).
- Единый контур для управления проблемами (`assurance`).
- Модули не привязаны к конкретным людям (роли живут в задачах).

## Что уже есть на рынке (конкуренты)

- **Backstage** — каталог сервисов, но не проверяет drift (расхождение с кодом). Это фреймворк, нужна команда для поддержки.
- **Port / OpsLevel** — SaaS-каталоги со скоркардами, недавно добавили MCP-интерфейсы. Но они не проверяют архитектурный drift и не строят граф связей из AST кода.
- **Compass** — каталог от Atlassian. Полезен только если вся компания замкнута на Jira/Confluence.
- **Structurizr / IcePanel** — редакторы C4-диаграмм. Но это ручная отрисовка картинок, а не живой граф из кода.
- **Swimm** — начинали с docs drift на сниппетах кода, но в 2026 году ушли в агентский контекст как ручную услугу (service). Archon делает это автоматически как продукт.

**Наша ниша:** мы объединяем контроль архитектурного дрейфа (Zero Drift) и живой контекст для AI-агентов через MCP. Документация не просто не врёт — она пишется системой и гарантирует корректную работу AI-разработки.

## Риски (если спросят "а что может пойти не так")

- Анализ конкурентов — черновик, цены/релизы не проверены с их сайтов.
- Сценарии использования писал один человек — нужна внешняя проверка (интервью с реальными пользователями).
- Есть 3 открытых вопроса (OQ-1, OQ-2, OQ-8), которые блокируют код. Пока они не решены — код не пишем.

## Ожидаемые вопросы

**"Почему не сделать плагин к Backstage?"**
Наша главная ценность — движок, который читает код и сверяет с документами. Портал совместим с форматом Backstage — мы не конкурируем, а дополняем.

**"Зачем два способа читать код (extract и interpret)?"**
`extract` — точно и дешево (парсит синтаксис). `interpret` — понимает смысл через LLM, но дорого и может ошибаться. Если смешать — не поймёшь, где факт, а где предположение.

**"Кто владелец модуля?"**
Никто. Модули — это архитектура, а не зоны ответственности людей. Задача может затрагивать несколько модулей. Владелец есть у задачи, не у модуля.

**"Когда начнёте писать код?"**
После того, как закроем 3 блокирующих вопроса (судьба прототипа, где хранить модель, как разворачивать систему).
