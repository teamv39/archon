## 2. Твои полномочия и правила игры

### Репозиторий `teamv39/archon-portal`
* Ты — главный хозяин репозитория витрины и ключевой проверяющий (Primary Reviewer).
* Все изменения идут через Pull Request из веток `feature/<task-id>-kebab` в `main`.
* Твой апрув — достаточный для мержа PR. Ждать апрува Дениса не нужно, кроме двух случаев:
  1. Меняются общие контракты данных с ядром платформы (`archon-core-service`).
  2. Тебе самому требуется второе мнение по сложной архитектурной развилке.

### Контракты и Mock-First
* Ты задаешь формат данных, на которых работает фронтенд.
* Если Паша (бэкенд ядра) еще не написал боевой эндпоинт, ты описываешь структуру синтетического JSON в мок-сервере, согласуешь ее с Кириллом и отдаешь в разработку. Команда витрины никогда не простаивает в ожидании ядра.

### Связка с дизайном
* Ты вместе с Кириллом валидируешь макеты Кати в Figma.
* Главный критерий приемки дизайна: компоненты должны естественно ложиться на библиотеку `shadcn/ui` и токены Tailwind CSS (палитра zinc/slate). Если в макетах появляется сложная кастомная анимация или нестандартный контрол, который придется верстать неделю с нуля — ты возвращаешь макет на доработку.

## 3. Операционный ритм команды

Чтобы не выгорать на созвонах и не отвлекаться от кода:

### Короткие синки (15 минут максимум)
* Не проводи часовых совещаний. Достаточно одного созвона в середине недели на 15 минут.
* Формат простой: каждый отвечает на 3 вопроса:
  1. Что сделал за последние 2-3 дня?
  2. Что делаешь дальше?
  3. Где застрял или кто тебя блокирует?
* Все остальные вопросы решаются текстом в рабочем чате или в комментариях к тикетам на GitHub.

### Код-ревью без задержек
* Старайся не мариновать чужие PR дольше 24 часов. Если PR висит днями, разработчик теряет темп.
* **Чек-лист быстрой проверки PR:**
  - [ ] Код компилируется без ошибок (`npm run build`, `tsc --noEmit`);
  - [ ] Линтер не ругается (`npm run lint`);
  - [ ] Нет захардкоженных секретов, токенов или абсолютных локальных путей;
  - [ ] Компоненты используют типы TypeScript, а не `any`;
  - [ ] Название PR и ветки содержит номер задачи (например, `ARCH-38`).
