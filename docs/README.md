# Документация проекта Archon

> **Раздел:** `docs/` (Каталог документации)  
> **Статус:** Актуально (Фаза 0: Product & Business Analysis)  
> **Навигация:** [Корень проекта](../README.md) | [Полный индекс](INDEX.md) | [Инструкция для LLM](../AGENTS.md)

Вся техническая документация хранится в Git вместе с кодом. Confluence используется только для бизнес-контекста и cross-team collaboration.

## Структура документации

### `/docs/adr/` — Architecture Decision Records
Запись всех значимых архитектурных решений. Каждое решение = отдельный файл.

Формат: `NNNN-title.md` (например, `0001-docs-as-code.md`)

### `/docs/architecture/` — High-Level Design & Modules
Общая архитектура системы, реестр 17 логических модулей фабрики, топология процессов, контракты и модель данных.

### `/docs/research/` — Research & Analysis
Результаты исследований: анализ рынка, конкуренты, интервью, архитектурные слои.

### `/docs/design/` — UI/UX & Product Design
Дизайн-документы клиентской витрины: CJM, вайрфреймы, спецификации экранов.

### `/docs/guides/` — Guides & Onboarding
Практические руководства: шпаргалки для разработчиков, тимлидов и планы обучения витрине.

### `/docs/nfr/` — Non-Functional Requirements
Требования к производительности, масштабируемости, безопасности, observability.

### `/docs/api/` — API Specifications
Контуры взаимодействия, спецификации REST OpenAPI, MCP и контракты интеграций.

## Принципы работы с документацией

1. **Source of truth — Git, не Confluence**
   Технические детали живут в репозитории. Confluence для бизнес-контекста.

2. **ADR для каждого важного решения**
   Выбрали технологию? Изменили подход? Зафиксируй ADR.

3. **Документация вместе с кодом**
   Изменения в коде = изменения в документации в том же PR.

4. **Автогенерация где возможно**
   API specs, диаграммы, метрики — генерируем из кода и конфигов.

5. **Ревью документации = часть code review**
   Документация ревьюится так же строго, как код.

## Шаблоны

Шаблоны для ADR и других документов находятся в соответствующих директориях.
