# ТЗ на дизайн: Инбокс находок и верификация (Assurance Inbox)

* **Роут:** `/findings`
* **Роль в продукте:** Главный рабочий экран архитектора и техлида. Интерфейс Human-in-the-Loop для валидации доказательной базы (Evidence Review) и принятия решений по расхождениям между кодом и документацией.
* **Исполнители:** Екатерина (Figma), Кирилл (React/Tailwind/shadcn), Артем (BFF эндпоинты `/api/findings` и мутации `/api/findings/:id/decision`).

---

## 1. Задачи пользователя (JTBD)

1. **Архитектор / Тимлид:** разобрать очередь найденных расхождений (Spec-Drift), изучить доказательства (конкретные строки кода против документации) и за 15 секунд принять взвешенное решение: подтвердить дефект, согласовать временный риск или отклонить ложное срабатывание.
2. **Лид комплаенса:** посмотреть реестр всех согласованных архитектурных рисков (техдолг) и сроки их истечения.

---

## 2. Структура экрана (Layout)

Реализуется по паттерну Master-Detail (список слева + выдвижная шторка деталей справа шириной 50% экрана):

```
┌────────────────────────────────────────────────────────────────────────┐
│ Инбокс находок          [Все: 12] [Новые: 8] [В работе: 3] [Риски: 1]  │ Header
├────────────────────────────────────────────────────────────────────────┤
│ [ Поиск по файлам/сервисам... ] [Критичность ▼] [Сервис ▼] [Команда ▼] │ Toolbar
├───────────────────────────────────┬────────────────────────────────────┤
│ Таблица находок (Master List)     │ Панель Evidence Review (Detail)    │
│                                   │                                    │
│ > FINDING-104  billing-service    │ FINDING-104: Недокументированный роут
│   Critical • Undocumented Route   │ ────────────────────────────────── │
│   2h ago • New                    │ Документация    vs   Код (AST)     │
│                                   │ [docs/api.md]        [src/client.py]│
│   FINDING-105  auth-service       │                                    │
│   High • Ghost Dependency         │ Заключение анализатора             │
│   5h ago • Confirmed              │ ────────────────────────────────── │
│                                   │ [Подтвердить] [Принять риск] [FP]  │
└───────────────────────────────────┴────────────────────────────────────┘
```

## 3. Функциональные требования к списку (Master List)

### 3.1. Шапка и быстрые фильтры-табы
* **Заголовок:** «Инбокс находок» (Assurance Inbox).
* **Табы статусов:**
  * `Все активные (12)`
  * `Новые (8)` — по умолчанию
  * `Подтвержденные (3)`
  * `Принятые риски (1)` (Реестр архитектурного техдолга)
  * `Архив / Закрытые`

### 3.2. Панель фильтрации
* Поиск по ID находки, имени сервиса или пути к файлу.
* Фильтры: Критичность (`Critical`, `High`, `Medium`, `Low`), Сервис, Команда.

### 3.3. Состав строки таблицы
* **Индикатор критичности:** цветовая вертикальная полоса слева (красный для `Critical`, оранжевый для `High`, желтый для `Medium`).
* **Идентификатор:** `FINDING-104` (моноширинный текст).
* **Сервис:** имя сервиса (например, `billing-service`).
* **Тип проблемы:** бейдж категории (`Undocumented Endpoint`, `Broken Dependency`, `Schema Mismatch`).
* **Краткое резюме:** однострочная суть проблемы («Код вызывает эндпоинт /v2/pay, в документации описан /v1/pay»).
* **Возраст:** `2h ago` (тултип с точным временем и Git commit SHA).
* **Текущий статус:** `New`, `Confirmed`, `Risk Accepted`.
* **Интерактивность:** Клик по строке выделяет ее и открывает панель Evidence Review.

## 4. Панель доказательной базы (Evidence Review Drawer)

Выдвигается справа при выборе строки или открывается как сплит-панель:

### 4.1. Шапка панели
* ID находки (`FINDING-104`), бейдж критичности и текущий статус.
* Ссылка на паспорт связанного сервиса.
* Кнопка закрытия панели (`Esc` или крестик).

### 4.2. Блок сравнительного анализа (Evidence Diff Viewer)
Главный блок экрана — двухколоночное сопоставление первоисточников:

```
┌─────────────────────────────────┬─────────────────────────────────┐
│ ДОКУМЕНТАЦИЯ                    │ ИСХОДНЫЙ КОД (AST-факт)         │
│ docs/architecture/payments.md   │ src/gateway/client.py#L42-L48   │
├─────────────────────────────────┼─────────────────────────────────┤
│ "Сервис обращается к платежному │ 42 | def charge_card(payload):  │
│ шлюзу по контракту v1:          │ 43 |   return http_post(        │
│ POST /api/v1/charge"            │ 44 |     url="/api/v2/charge",  │
│                                 │ 45 |     json=payload           │
│                                 │ 46 |   )                        │
└─────────────────────────────────┴─────────────────────────────────┘
```

* **Левая колонка («Документация»):**
  * Путь к markdown-файлу в репозитории со ссылкой на GitHub.
  * Цитата из текста спецификации с подсветкой несовпадающего фрагмента.
* **Правая колонка («Код»):**
  * Путь к файлу исходного кода с точным диапазоном строк (`#L42-L48`).
  * Фрагмент кода с номерами строк и подсветкой синтаксиса.
* **Подвал блока:** Вердикт анализатора Archon:
  * Текстовое пояснение: *«Синтаксический разбор AST зафиксировал вызов роута /v2/charge, тогда как проектный документ фиксирует устаревшую версию /v1/charge. Вероятность расхождения: 100% (детерминированное несовпадение)»*.

---

### 4.3. Панель принятия решений (Decision Actions)
Закрепленный футер панели с тремя кнопками решений:

1. **Кнопка «Подтвердить расхождение» (Confirm):**
   * Переводит находку в статус `Confirmed`.
   * Открывает диалог с готовым описанием для создания тикета в Jira/GitHub Issues или копирования ссылки для инженера.
2. **Кнопка «Принять риск» (Accept Risk):**
   * Вызывает модальное окно:
     * *Поле 1 (Обязательное):* Обоснование риска («Почему отклонение допустимо сейчас»).
     * *Поле 2 (Обязательное):* Срок действия (30 дней, 60 дней, 90 дней, бессрочно).
   * После подтверждения находка переходит в статус `Risk Accepted` и убирается из счетчика критических проблем.
3. **Кнопка «Ложная тревога» (False Positive):**
   * Отклоняет находку. Опциональное поле комментария: «Почему это не является ошибкой» (используется для корректировки правил парсера).

## 5. Состояния экрана (States)

1. **Zero Drift State (Empty State):**
   * Если в фильтре «Новые» 0 элементов:
   * Нейтральная спокойная графика: «Расхождений не обнаружено. Архитектурная документация на 100% синхронизирована с кодом».
2. **Loading State:** Скелетон таблицы на 6 строк и скелетон панели деталей.
3. **Optimistic Mutation:** При клике «Принять риск» статус в таблице меняется мгновенно без блокировки интерфейса, в углу появляется toast с кнопкой «Отменить».
