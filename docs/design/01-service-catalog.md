# ТЗ на дизайн: Каталог сервисов (Service Catalog)

* **Роут:** `/services`
* **Роль в продукте:** Главная витрина всех программных компонентов компании, диспетчерская здоровья архитектуры и точка входа в досье сервисов.
* **Исполнители:** Екатерина (Figma), Кирилл (React/Tailwind/shadcn), Артем (BFF эндпоинты `/api/services`).

---

## 1. Задачи пользователя (JTBD)

1. **Разработчик:** мгновенно найти целевой сервис (по названию, тегу или команде) и в один клик перейти в его паспорт либо Git-репозиторий.
2. **Тимлид / Архитектор:** оценить масштаб дрейфа документации по парку микросервисов, локализовать проблемные компоненты и экспортировать реестр.

## 3. Функциональные требования к блокам

### 3.1. Шапка экрана (Header)
* **Заголовок:** «Каталог сервисов».
* **Индикаторы-счетчики (Quick Filters):**
  * `Всего: N` (нейтральный серый);
  * `В синхроне: K` (зеленый бейдж);
  * `С дрейфом: M` (красный бейдж, клик активирует фильтр «Только с дрейфом»);
  * `Принятые риски: R` (желтый бейдж).
* **Глобальное действие:** Кнопка «Экспорт реестра» (выпадающий список: CSV, JSON).

### 3.2. Панель управления (Toolbar)
* **Поле живого поиска:** моментальная фильтрация по подстроке без перезагрузки (название сервиса, описание, ключевые слова).
* **Фильтры (Dropdown Selects):**
  * *Статус дрейфа:* Все / Только с дрейфом / В синхроне / Принятые риски;
  * *Критичность (Tier):* Все / Tier-1 (Mission Critical) / Tier-2 / Tier-3;
  * *Команда (Owner):* список зарегистрированных команд (например, `@payments`, `@auth`, `@platform`);
  * *Стек технологий:* языки программирования и хранилища (Kotlin, Python, PostgreSQL, Kafka).
* **Переключатель отображения (View Toggle):** тумблер с иконками:
  * Режим 1: Таблица (Table View) — активен по умолчанию;
  * Режим 2: Карточки (Card Grid View).

## 4. Спецификация режимов отображения

### 4.1. Режим 1: Таблица высокой плотности (Table View)
Компонент на базе `@tanstack/react-table` со строгой темной разметкой:

| Колонка | Описание поля | Интерактивность |
| :--- | :--- | :--- |
| **Сервис** | Жирное имя сервиса (моноширинный шрифт, например `billing-service`) + краткое описание сервиса под ним (серый цвет, `text-xs`). | Клик по имени открывает Паспорт сервиса (`/services/:id`). Рядом мини-иконка внешней ссылки на GitHub/GitLab. |
| **Критичность** | Компактный бейдж: `Tier-1` (пурпурный/синий), `Tier-2` (серый), `Tier-3` (темно-серый). | Тултип с описанием уровня критичности. |
| **Статус дрейфа** | Семантический цветной бейдж:<br>• `In Sync` (зеленый фон/текст);<br>• `Drift: 2` (красный фон/текст);<br>• `Risk Accepted` (желтый фон/текст). | **Клик по красному бейджу:** переход в Инбокс находок с предфильтром по этому сервису. |
| **Команда** | Бейдж команды (например, `@payments`). | Клик фильтрует таблицу по выбранной команде. |
| **Стек** | Теги технологий (до 3 тегов: `Kotlin`, `PG`, `Kafka`, скрытые под капотом `+2`). | Тултип с полным перечнем технологий. |
| **Связи** | Индикатор зависимостей: `↑ 3 / ↓ 7` (3 входящих клиента, 7 исходящих вызовов). | Тултип с перечнем ключевых связанных сервисов. |
| **Синхронизация** | Относительное время последнего сканирования: `12m ago`. | Тултип с точной датой и SHA коммита. |
| **Меню (`...`)** | Выпадающее меню действий. | • Открыть паспорт<br>• Показать на C4-карте<br>• Скопировать MCP ID<br>• Открыть репозиторий |

*Сортировка по умолчанию:* сервисы со статусом `Drift Detected` поднимаются наверх таблицы.

---

### 4.2. Режим 2: Сетка карточек (Card Grid View)
Адаптивная сетка карточек (2–3 колонки на десктопе):

* **Шапка карточки (Card Header):**
  * Название сервиса жирным шрифтом (`text-base font-semibold`).
  * Бейдж Tier (`Tier-1`).
  * Бейдж статуса дрейфа (`In Sync` зеленый или `Drift: 2` красный).
* **Тело карточки (Card Body):**
  * Текстовое описание сервиса (до 3 строк, обрезка троеточием `line-clamp-3`).
  * Бейдж команды (`@payments`).
  * Горизонтальный ряд тегов используемого стека (`Kotlin`, `PostgreSQL`, `Kafka`).
* **Подвал карточки (Card Footer):**
  * Индикатор связей: `3 входящих • 7 исходящих`.
  * Время синхронизации: `Синхронизировано 12м назад`.
  * Прямая ссылка на Git-репозиторий.
* **Поведение:** Клик по карточке открывает `/services/:id`.

## 5. Состояния экрана (States)

1. **Loading State:** Скелетон таблицы на 8 строк или сетка из 6 скелетон-карточек (`shadcn/skeleton`) с мерцающими полосами.
2. **Empty Filter State:** Если поиск не дал результатов:
   * Текст: «Сервисы по заданным критериям не найдены».
   * Кнопка: «Сбросить фильтры».
3. **Empty Platform State (организация без сервисов):**
   * Текст: «В организации пока нет подключенных сервисов».
   * Действие: кнопка «Подключить GitHub App».
4. **Error State:** Баннер ошибки загрузки данных от BFF с кнопкой «Повторить запрос».
