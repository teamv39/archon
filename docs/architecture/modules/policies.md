# `policies` — ищет архитектурные проблемы в графе

Статус: new
Компетенция: архитектура, правила, анализ графов
Зависит от: model, resolve (склеенный граф)
Используется: assurance, portal

## Назначение

Проверяет граф на архитектурные нарушения. Правила описываются кодом, а не зашиваются в продукт: команды могут расширять набор без релиза. А появление находки фиксируется там же, где видны все остальные.

## Что делает

- Держит декларативные правила над графом. Черновой список примеров: общая база данных у двух сервисов, циклические зависимости, обход шлюза, необъявленные зависимости. Окончательный набор не определён.
- Вычисляет находки по этим правилам.
- Не хранит находки и их статусы — граф читает через API `model`, а найденное пишет в `assurance`. Статусы, жизненный цикл и принятие риска — за `assurance`.

## Данные

Свои правила и их версионирование. Больше ничего: граф и находки живут не здесь.

## Форма деплоя

Сборочная единица **`archon-core-service`** (Kotlin / JVM) согласно [ADR-0007](../../adr/0007-saas-process-topology-and-packaging.md) и [`deployment.md`](../deployment.md). Движок валидации правил (Open Policy Agent / Cypher инварианты) исполняется in-process в JVM бэкенда.

## Открытые вопросы

- Набор архитектурных инвариантов и связь правил с конфигурацией `registry`.
- OQ-2 закрыт в [ADR-0003](../../adr/0003-source-of-truth-and-tenant-isolation.md) (структура графа определена в Apache AGE / openCypher).
- OQ-8 закрыт в [ADR-0007](../../adr/0007-saas-process-topology-and-packaging.md).

## Решения

- ADR-0004 (отделён от бывшего единого модуля проверки; разделен с `drift` по инфраструктуре вычислений).
- ADR-0007 (упаковка движка политик в `archon-core-service`).

## Заметки

С `drift` у этого модуля общий только внешний облик — оба выдают находки — но не данные. Сводить их в один модуль — потерять границу стоимости.
