# `resolve` — глобальная склейка сущностей

Статус: new
Зависит от: model, registry
Используется: policies, drift, portal, export

## Назначение

Делает из множества репозиториев одну систему: склеивает сущности, которые
упоминаются под разными именами в разных репо (shared-сервис, топик, БД),
дедуплицирует общие инфраструктурные узлы и собирает `Landscape` — агрегат
всех продуктов.

Атака A4: ни один модуль старой декомпозиции не владел корпусом как единым
целым. Те же симптомы — ручной `shared/externals.c4` в archmap и невозможность
вычислить "цикл между сервисами из трёх репо", не имея одновременно всю
картину.

## Что делает

- Батч-проход по корпусу: совместная нормализация сущностей.
- Разрешение идентичности (канонические имена — то, где не сработал
  `shared/externals.c4`; отклонённый подход там — причина появления этого
  модуля).
- Сборка landscape (C0 уровня C4): дерево продуктов -> сервисов репозиториев.
- Владелец OQ-7 ("как склеивать") — абстрактный вопрос получает хозяина.

Не делает: не извлекает, не хранит (`model` хранит; `resolve` вычисляет), не
ставит диагнозы (`policies`/`drift` на готовом склеенном графе).

## Интерфейсы

- **Вход:** снапшот `model` по всему корпусу.
- **Выход:** склеенные узлы + `Landscape` обратно в `model` или рядом как
  материализованное представление — TBD (OQ-2, OQ-13).

## Данные

Результат — глобальная карта идентичностей и landscape; правило склейки
(config/heuristics) — хранится и версионируется здесь.
