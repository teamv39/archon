# `extract` — детерминированное извлечение фактов

Статус: new
Компетенция: компиляторы, парсеры, манифесты, языки
Зависит от: sources, registry
Используется: reconcile, model (косвенно), resolve

## Назначение

Вытаскивает из кода факты, которые можно назвать однозначно: вызовы между
сервисами, контракты (OpenAPI/gRPC/AsyncAPI), подключения к БД, зависимости
из build-файлов. Дешёвый, детерминированный, без галлюцинаций — атомная
опора для `policies` и для склейки в `resolve`.

До ревизии жил как половина большого `m1` вместе с LLM-контуром. Атака A2
показала: разные владельцы, разная экономика, разные причины падать и разный
цикл изменений — это два модуля, а не один.

## Что делает

- Парсинг AST и манифестов (build-файлы, compose-манифесты, спецификации API).
- Нормализация в записи-факты — фрагменты будущей Extraction Contract.
- Сигнал: "вот точный факт с координатами в коде, за него ручаемся".

Не делает: не понимает, что компонент "значит" для бизнеса; не решает,
что факт означает нарушение; не хранит историю (`model`); не решает
конфликт с `interpret` (`reconcile`).

## Интерфейсы

- **Вход:** снапшоты и события `sources`.
- **Выход:** поток фактов в `reconcile`, оформленный будущей Extraction
  Contract (форма не зафиксирована, OQ-3).

## Данные

Stateless в идее: вход — код, выход — факты. Промежуточные артефакты прогонов
(черновики, логи парсера) — TBD (OQ-8).

## Форма деплоя

TBD (OQ-8). Ближайший сосед по сборочной единице — `interpret` и `reconcile`

## Открытые вопросы

- OQ-3 (форма контракта), OQ-6 (инкрементальность), OQ-9 (словарь), OQ-11.

## Решения

- ADR-0004 (разделён из `m1`, атака A2)

## Заметки

Здесь — место, где появляется `provenance` факта ("это сказал парсер X с
такой-то версией"). Без provenance `reconcile` не сможет решать споры, а
`model` — показывать trust.
