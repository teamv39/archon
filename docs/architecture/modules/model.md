# `model` — хранит граф связей о системе

Статус: blocked (OQ-2)
Зависит от: reconcile
Используется: resolve, policies, drift, assurance, portal, pr-bot, chat-bot, export

## Назначение

Единое хранилище, где живёт граф системы: узлы — сервисы, базы, очереди, документы — и связи между ними. Граф сохраняется между перезапусками, версионируется (можно посмотреть, как выглядела система на любой коммит) и доступен для запросов. Без этого модуля Archon остаётся генератором картинок. Все остальные модули либо пишут в граф, либо читают из него, ничего не дублируя.

## Что делает

- Хранит узлы и связи. Черновой состав — в `../data-model.md`.
- Ведёт версии и историю: «что было на коммит X», чем граф в одной версии отличается от другой.
- Даёт единый API для запросов: поиск, выборки, анализ влияния («что сломается, если поменять этот сервис»). API должен быть одним для всех верхних слоёв — портала, бота в PR, чат-бота и экспорта — и отдавать и структуру, и текст, и короткую ссылку. Если для четырёх каналов нужны четыре разных API — значит, API спроектирован плохо.
- Даёт постоянные ссылки на любой элемент графа — чтобы из уведомления, отчёта или сообщения бота можно было перейти точно в нужное место. Сейчас такой ссылки нет, это известная прореха.
- Сводит изменения: если человек поправил что-то вручную, следующий автоматический прогон не должен затереть его правку. В прототипе archmap эта проблема уже возникала.

Не делает: не извлекает факты из кода (`extract`/`interpret`), не примиряет противоречия (`reconcile`), не склеивает сущности между репозиториями (`resolve`), не проверяет правила (`policies`), не сопоставляет документы с кодом (`drift`), не ведёт проверку человеком (`assurance`).

## Интерфейсы

- **Вход:** согласованные факты из `reconcile`; правки человека через pull/merge request; статусы доверия из `assurance`.
- **Выход:** API запросов для всех потребителей выше.

## Данные

Главный нерешённый вопрос продукта (OQ-2): где источник правды — файлы в git, графовая база или гибрид (файлы в git как главный источник, база как пересобираемый индекс). Пока он не решён, всё остальное подвешено: выбор движка базы (OQ-5), схема данных, стратегия сведения правок. **Модуль нельзя начинать кодить до решения OQ-2** — это самый хрупкий узел системы.

## Заметки

- Модель данных (`../data-model.md`) — черновик, её пересмотрят после решения OQ-2. Там же есть сущности без владельца — нужен отдельный проход «каждая сущность → ответственный модуль».
- Идеи прототипа archmap (`.c4`-файлы в git, правки через merge request, пометка `#manual_check`) работают только в варианте «git как источник правды». Если выберем базу как источник правды, от наследия прототипа останется лишь часть.
