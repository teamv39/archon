# `interpret` — LLM-интерпретация смыслов

Статус: prototype
Компетенция: LLM, промпт-инжиниринг, метрики качества
Зависит от: sources, registry
Используется: reconcile

## Назначение

Выводит то, что из AST не читается: назначение компонента, бизнес- flows,
уровни C2-C3, роли сервисов, разметка неясных мест. Даёт смысл, который
превращает факты `extract` в объяснимую архитектуру.

Дорогой и вероятностный контур: деньги и latency на каждый прогон, зависимость
от модели и промптов, риск галлюцинаций. Потому же — выделен в отдельный
модуль: бюджеты и метрики у него другие, чем у `extract` (атака A2, OQ-15).

## Что делает

- Отбор файлов на анализ (в archmap — отдельный LLM File Selector).
- Генерация JSON-модели по Extraction Contract из кода + документации.
- Метки `confidence` и `#manual_check` для мест, где нужно присутствие
  человека.

Не делает: не заявляет факты, за которые ручается безоговорочно — это к
`extract`; не решает противоречия с `extract` (`reconcile`); не хранит
граф (`model`).

## Интерфейсы

- **Вход:** те же снапшоты `sources`, плюс справочники `registry` (словарь).
- **Выход:** кандидаты на факты в `reconcile`, с provenance и confidence
  (форма — та же Extraction Contract, но со свидетельствами неуверенности).

## Данные

Хранит промпты, шаблоны, регрессионные наборы для метрик точности.
Ещё нет: метрики точности, воспроизводимость между прогонами, поведение на
грязных репозиториях.
