# `registry` — конфигурация корпуса

Статус: new
Зависит от: platform (RBAC — кто имеет право это менять)
Используется: sources, resolve, policies, drift, runtime

## Назначение

Хранит то, что Archon знает про конкретного клиента: какие репозитории мы
вообще анализируем и как они связаны с продуктами, командами, правилами. Без
этого модуля невозможны ни landscape (нужна привязка сервис -> продукт), ни
нормальный Passport (нужна привязка к Jira-команде), ни словарь тегов (OQ-9).
Атака A7: ни один модуль старой декомпозиции не владел "описанием самого
клиента".

## Что делает

- Реестр репозиториев: что читаем, какой скоуп, что игнорируем.
- Привязки: repo -> product -> team.
- Словарь/теги (OQ-9): канонические названия, доменные ярлыки.
- Наборы правил: какие policy-suites включены для этого tenant.
- Версионирование конфигурации (она меняется и влияет на результаты).

Не делает: не ходит ни в какие внешние системы (`sources`), не хранит граф
(`model`), не решает, кто имеет право менять конфиг (`platform`).

## Интерфейсы

- **Вход:** настройки от администратора tenant (UI `portal` / API).
- **Выход:** запросы `sources` ("что читать"), скоупы и привязки для
  `resolve`/`policies`/`drift`, расписание/бюджетные метки для `runtime`.

## Данные

Собственная конфигурационная модель, tenant-scoped. Хранится у себя; кандидат
на совместное хранение с `sources` при физической топологии (OQ-8).
