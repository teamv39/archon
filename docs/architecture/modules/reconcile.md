# `reconcile` — примирение источников фактов

Статус: new
Зависит от: extract, interpret
Используется: model

## Назначение

Точка, где факты из `extract` (детерминированные) и `interpret` (LLM)
сводятся в один взгляд на систему. Когда источники противоречат — решает, что
побеждает и почему. Именно здесь рождается provenance: "этот факт сказал
парсер, этот — модель с confidence 0.6, вот где они разошлись".

Старая декомпозиция прятала эту операцию внутри `m1`, и OQ-4 ("кто побеждает
при противоречии") висел без хозяина. ADR-0004 закрепил: примирение —
отдельный модуль, потому что размазать его по путям записи в граф — значит
заставить каждый путь заново изобретать семантику конфликтов.

## Что делает

- Сопоставление фактов двух контуров по одной сущности.
- Разрешение конфликтов по правилам приоритета (AST > LLM для структурных
  фактов и наоборот для смысловых — правила TBD, OQ-4).
- Прикрепление provenance и confidence к каждому факту.
- Выставление `#manual_check` / в очередь `assurance`, когда автоматическое
  примирение невозможно.

Не делает: не извлекает (contours выше), не хранит (`model`), не ведёт
человеческий workflow (`assurance` — ему этот модуль только передаёт
очередь).

## Интерфейсы

- **Вход:** Extraction Contract из `extract` и `interpret` (одна схема).
- **Выход:** разрешённые факты + журнал конфликтов в `model`; очередь на
  проверку в `assurance`.

## Данные

Правил примирения (config-driven, на уровне tenant через `registry`).
Собственного графа не имеет.
