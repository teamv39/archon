# `reconcile` — разрешает конфликты, если источники сказали разное

Статус: new
Зависит от: extract, interpret
Используется: model

## Назначение

Точка, где факты из двух путей — детерминированного (`extract`) и модельного (`interpret`) — сводятся в один непротиворечивый взгляд на систему. Если источники противоречат друг другу, этот модуль решает, что побеждает и почему. Здесь же рождается происхождение каждого факта: «этот факт извлечён парсером из кода, этот — моделью с уверенностью 0.6, а вот где они разошлись».

Раньше эта логика была спрятана внутри одного большого модуля извлечения, и вопрос «кто прав при противоречии» висел без владельца. В ADR-0004 примирение выделили в отдельный модуль: если размазать его по всем местам записи в граф, каждое будет заново изобретать, как понимать конфликты.

## Что делает

- Сопоставляет факты двух путей об одной и той же сущности.
- Разрешает конфликты по правилам приоритета: для структурных фактов побеждает то, что извлечено из кода напрямую; для смысловых — наоборот. Сами правила пока не определены (это вопрос с владельцем — см. «Открытые вопросы»).
- К каждому факту прикрепляет, откуда он взялся и насколько ему можно доверять.
- Если автоматически договориться нельзя — помечает факт для ручной проверки и отправляет в очередь `assurance`.

Не делает: не извлекает сам (это делают два пути выше), не хранит (`model`), не ведёт проверку человеком (`assurance` — этот модуль лишь передаёт ему очередь).

## Интерфейсы

- **Вход:** факты от `extract` и `interpret` в едином формате (контракт извлечения).
- **Выход:** согласованные факты и журнал конфликтов — в `model`; очередь на проверку — в `assurance`.

## Данные

Правила примирения — конфигурируемые, настраиваются отдельно для каждого клиента через `registry`. Собственного графа не имеет.

## Открытые вопросы

- OQ-4 (приоритеты при противоречиях источников — теперь у вопроса есть владелец).

## Решения

- ADR-0004 (модуль создан: бывший единый контур извлечения разделён на детерминированный, модельный и примиряющий — у них разная стоимость, разные причины сбоев и разная скорость изменений).

## Заметки

Происхождение фактов, которое рождается здесь, — это то, на чём держатся статусы доверия в `assurance`, объяснение находок в `pr-bot` и сведение ручных правок в `model`. Это не деталь конвейера, а фундамент объяснимости всего продукта.
