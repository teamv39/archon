# `platform` — enterprise-обвязка

Статус: new
Зависит от: нет (обслуживает остальные)
Используется: все модули

## Назначение

Отделяет «набор сервисов» от «платформы»: с этим модулем продукт можно продавать корпоративным клиентам, без него это внутренний скрипт. Отвечает за то, кто что видит, и за то, чтобы ничего не утекало наружу.

## Что делает

- Единый вход в систему (через стандарты корпоративной аутентификации — единая модель прав для всех модулей: кто может читать, писать, принимать решения).
- Журнал действий — особенно решений из `assurance` (нужно для аудита, в том числе регуляторного).
- Изоляция данных нескольких клиентов на одной установке.
- Управление секретами — чтобы токены доступа не лежали в открытом виде, как это было в прототипе (в рабочей таблице).
- Упаковка для развёртывания в инфраструктуре заказчика.

## Форма деплоя

Сборочная единица **`archon-core-service`** (Kotlin / JVM) согласно [ADR-0007](../../adr/0007-saas-process-topology-and-packaging.md) и [`deployment.md`](../deployment.md). Реализует аутентификацию (GitHub OAuth / Keycloak), multi-tenancy контекст (`tenant_id`), маршрутизацию схем `tenant_<id>` в Apache AGE и аудит-лог.

## Решения

- ADR-0004 (выделение платформенной обвязки).
- ADR-0006 (модель Managed SaaS и авторизация).
- ADR-0007 (упаковка платформенного контура в `archon-core-service`).

## Заметки

Решения `assurance` должны попадать в журнал здесь, через единый механизм, а не копированием логики в каждый модуль.
