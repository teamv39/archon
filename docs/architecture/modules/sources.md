# `sources` — коннекторы к внешним системам (как подключиться к Git, Jira, Confluence)

Статус: spec
Компетенция: интеграции, API провайдеров (Git/Jira/Confluence)
Зависит от: registry (что читать), platform (секреты, права доступа)
Используется: extract, interpret, drift, resolve

## Назначение

Единая точка входа внешних данных: репозитории, Jira, Confluence, мессенджеры. Остальные модули не ходят в GitHub/GitLab/Bitbucket напрямую каждый по-своему — в прототипе, например, это делалось по-разному на каждый прогон.

## Что делает

- Читает репозитории: клонирует или обращается через API деревьев, считает разницу между коммитами, перечисляет файлы.
- Принимает уведомления «репозиторий изменился» (webhooks).
- Держит коннекторы к Jira, Confluence, мессенджерам.
- Отдаёт сырые файлы вместе с информацией об источнике: где взялось, когда и в каком виде.

Где граница: этот модуль — только доставка и аутентификация. Он всегда отдаёт сырьё как есть. Приводить данные к внутренней модели — дело потребителя: `extract` и `interpret` для кода, `drift` для документов. Смысл данных `sources` не решает.

## Интерфейсы

- **Выход** в `extract`/`interpret`: событие «репозиторий изменился» + снимок файлов.
- **Выход** в `drift`: поток документов с метаданными.
- Форма событий и артефактов пока не зафиксирована (OQ-6).

## Данные

Сам ничего не хранит, кроме меток положения для непрерывного чтения (на каком коммите или странице остановились). Секреты — только через `platform`.
