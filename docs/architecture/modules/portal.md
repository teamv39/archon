# `portal` — веб-портал

Статус: new
Зависит от: model (API запросов), assurance, resolve (ландшафт)
Используется: — (терминальный канал)

## Назначение

Единая визуальная поверхность продукта: просмотрщик диаграмм, сводки по аномалиям и дрейфу, интерфейс проверки находок, карточки сервисов.

## Что делает

- Показывает граф системы (холст на `@xyflow/react` + `elkjs`, [ADR-0008](../../adr/0008-xyflow-replaces-likec4.md); предшественник — просмотрщик LikeC4 в прототипе archmap).
- Показывает сводки по аномалиям (`policies`) и по дрейфу (`drift`) — данные идут через `assurance`.
- Даёт интерфейс для решений человека: очередь на проверку, принятие риска, статусы доверия. Все действия уходят в `assurance`, а не в обход него.
- **Каталог сервисов и паспорт сервиса — это секция портала, а не отдельный модуль** (решение по умолчанию из ADR-0004, см. OQ-17). Паспорт — карточка с основным досье сервиса; собирается из графа, находок и привязок `registry`. Если внешним системам понадобится реестр сервисов через API, каталог вырастет в публичный API над `model` — и тогда вернётся как отдельный модуль. Вопрос пока открыт.

Своей копии данных не хранит: всё берёт из API запросов `model` и из `assurance`. Важно: паспорт не имеет права стать вторым источником правды о сервисе — иначе вернётся та самая проблема дрейфа, которую продукт и решает.

## Интерфейсы

- **Вход:** API запросов `model` (единый формат для всех каналов: структура + текст + короткая ссылка) и API `assurance`.
- **Выход:** человеку.

## Форма деплоя

Сборочная единица **`archon-portal`** (TypeScript, React 18+, Vite, Tailwind CSS, `shadcn/ui`, Nginx) согласно [ADR-0007](../../adr/0007-saas-process-topology-and-packaging.md) и [`deployment.md`](../deployment.md). Разрабатывается в отдельном репозитории `teamv39/archon-portal` по спецификациям экранов из [`docs/design/`](../../design/README.md).

## Открытые вопросы

- OQ-17 (каталог: секция портала или публичный API — вариант «секция» принят по умолчанию, полная форма открыта).
- OQ-8 закрыт в [ADR-0007](../../adr/0007-saas-process-topology-and-packaging.md).
- Библиотека отрисовки зафиксирована: `@xyflow/react` + `elkjs` ([ADR-0008](../../adr/0008-xyflow-replaces-likec4.md)).

## Решения

- ADR-0004 (каталог вошёл в портал как секция, а не отдельный модуль).
- ADR-0007 (выделение в отдельную SPA сборочную единицу `archon-portal`).
- ADR-0008 (визуализация на `@xyflow/react` + `elkjs` вместо LikeC4).

## Заметки

Все каналы витрины — портал, MCP-сервер, бот в PR, чат-бот и генератор экспорт — читают `model` через унифицированный Query API, и формы ответов обязаны совпадать. Если каналы не сходятся на одном API, проблема в API.
