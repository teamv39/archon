# `portal` — web-портал

Статус: new
Зависит от: model (query API), assurance, resolve (landscape)
Используется: — (терминальный канал)

## Назначение

Единая визуальная плоскость продукта: вьювер диаграмм, дашборды аномалий и
дрейфа, интерфейс ревью, карточки сервисов.

## Что делает

- Отображение графа (вьювер LikeC4; прототип-предшественник — viewer archmap).
- Дашборды аномалий (`policies`) и дрейфа (`drift`) через `assurance`.
- Интерфейс человеческого контура: очередь ревью, принятие риска,
  trust-статы — действия идут в `assurance`, не в обход него.
- **Каталог сервисов и Passport — секция портала**, не отдельный модуль
  (решение OQ-17 по дефолту ADR-0004). Карточка сервиса собирается из
  графа, находок и привязок `registry`. Если потребуется сервис-реестр для
  внешних систем — каталог вырастет в публичный API над `model`, и тогда
  вернётся как отдельный модуль (вопрос остаётся открытым).

Не хранит своей правды: всё через query API `model` и API `assurance`.
Важно: Passport не имеет права стать вторым источником правды про сервис —
иначе вернётся та самая проблема дрейфа, которую продукт решает.

## Интерфейсы

- **Вход:** query API `model` (мультимодальный выход — структура + текст +
  short link, требование A9/F2), API `assurance`.
- **Выход:** человеку.

## Заметки

Все каналы (портал, pr-bot, chat-bot, export) читают `model` через один query
API — совпадение форм не опционально. Если четыре канала не сходятся на одном
API, проблема в API.
