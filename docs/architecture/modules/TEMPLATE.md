# Шаблон файла модуля

Копировать в `docs/architecture/modules/<имя>.md`, заполнить, добавить строку
в реестр `README.md`.

Принципы:
- Файл описывает текущее состояние модуля. Споры и обоснования — в ADR,
  открытые вопросы — в `../open-questions.md`, здесь только ссылки.
- Коротко лучше, чем длинно и устаревшее. Пустые секции помечаем `TBD`, не
  выдумываем.
- **Имен людей нет** (ADR-0004): максимум — нужная компетенция.
- Объем ~100-150 строк. Растет дальше — выносим детали во вложенный файл.

---

```markdown
# `<название>` — <одна строка>

Используется: <модули>

## Назначение

## Интерфейсы

- **Вход:** от кого, в какой форме (event / API / файл).
- **Выход:** кому, в какой форме.
- Ссылки на контракты (Extraction Contract, query API и т.п.).

## Данные

Что модуль хранит у себя, где, в какой модели. Если не хранит — так и пишем.
```
