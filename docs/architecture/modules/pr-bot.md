# `pr-bot` — бот в Git: комментирует и блокирует расхождения кода и документации

Статус: new
Зависит от: model, extract (инкрементальный), interpret (инкрементальный), assurance
Используется: — (терминальный канал)

## Назначение

Подсвечивает архитектурные последствия pull request прямо там, где автор их увидит — в merge request. Без этого качество архитектуры остаётся вопросом внимательности ревьюера.

## Что делает

- Прогоняет контур извлечения не по всему репозиторию, а только по диффу запроса на слияние, и через `model` строит архитектурный дифф.
- Пишет комментарии в merge request: «появился доступ к чужой базе данных», «возник цикл зависимостей», «новый контракт без документации» — со ссылкой на сводку и с объяснением, откуда сделан вывод (происхождение фактов из `reconcile`).

Насколько глубоко интегрируется — пока не выбрано: только комментарии, блокирующие проверки платформы (например, статус-чеки, влияющие на автоматическое слияние) или что-то среднее.

## Открытые вопросы

- OQ-6 (событийная модель и инкрементальный анализ).
- Когда бот блокирует слияние, а когда только предупреждает. Это политика `policies`/`assurance`, а не решение самого канала: при проверке пользовательских сценариев канал подтвердил себя как чистый доставщик.

## Решения

- ADR-0004 (бывший канал доставки в PR).

## Заметки

Самый ценный канал с точки зрения миссии «документы не должны расходиться с кодом»: поймать расхождение до слияния дешевле, чем после.
