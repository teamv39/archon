# m1. `extractor` — извлечение модели системы

Статус: prototype (LLM-контур, в форме прототипа archmap) / new (AST-контур)
Владелец: Денис (метамодель контракта) + Паша (AST) + Миша (LLM)
Зависит от: e2
Используется: m2

## Назначение

Переводит код и конфигурацию в структурированные факты и модели. Это исходная
точка всего Zero Drift: без достоверного извлечения граф превращается в галерею
красивых, но непроверяемых картинок.

## Что делает

Два взаимодополняющих контура извлечения:

1. **Семантический (LLM).** Бизнес-контекст, назначение компонентов, flows,
   уровни C1-C3, разметка неясных мест. Дает смысл, который из AST не читается.
2. **Детерминированный (AST/парсеры манифестов).** Вызовы между сервисами,
   контракты (OpenAPI/gRPC/AsyncAPI), подключения к БД (сырье для детекции
   shared DB), зависимости из build-файлов. Дает факты, на которых держатся
   аномалии `m3`.

Не делает: не хранит историю (это `m2`), не визуализирует, не решает, что
из найденного является нарушением (`m3`).

## Интерфейсы

- **Вход:** события и снапшоты `e2`.
- **Выход:** Extraction Contract — версионируемая JSON-схема факта/модели
  (черновой набросок: JSON-выход экстракторов archmap, см. `../prototypes/archmap.md`).

Форма контракта не зафиксирована (OQ-3) и является самым важным интерфейсом
продукта.

## Данные

Модуль stateless по идее: вход — код, выход — контракт. Промежуточные
артефакты прогонов (отбор файлов, черновики) — где лежат, TBD (OQ-8).
