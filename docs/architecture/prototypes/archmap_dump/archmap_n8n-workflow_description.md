**archmap** — это конвейер автоматического создания и актуализации интерактивной архитектурной документации (в нотации **LikeC4**) напрямую из репозиториев с исходным кодом.

В отрыве от конкретных инструментов оркестрации (n8n, CI-воркеров или ботов) сквозной пайплайн представляет собой **5 последовательных этапов трансформации данных**: от дерева исходного кода до опубликованного интерактивного веб-портала.

---

```
[Исходный репозиторий]
         │
         ▼
[ 1. Сбор параметров ] ── (глубина анализа C1-C3, ссылки, токены)
         │
         ▼
[ 2. Двухфазный LLM-анализ ]
    ├── Фаза 1 (Selector): дерево репо + README ➔ список релевантных файлов
    └── Фаза 2 (Extractor): сырой код файлов + словарь терминов ➔ JSON-контракт модели
         │
         ▼
[ 3. Детерминированная кодогенерация ] ── (JSON ➔ LikeC4 DSL + дедупликация shared-систем)
         │
         ▼
[ 4. Публикация в реестр ] ── (изолированный project-пакет в Output Repo, автомерж)
         │
         ▼
[ 5. Сборка и деплой ] ── (likec4 build ➔ статический веб-сайт / Pages)
```

---

### Этап 1. Инициализация и сбор контекста
* **Входные данные:** ссылка на исходный репозиторий (Source Repo), уровень детализации (`Extraction Level`: C1-система, C2-контейнеры или C3-компоненты), целевое пространство для публикации и опциональный пользовательский промпт.
* **Действие:** проверка прав доступа к коду и фиксация конфигурации запуска.

---

### Этап 2. Двухфазный семантический анализ (LLM-парсер)
Чтобы не перегружать контекстное окно языковой модели содержимым всего репозитория, извлечение разделено на две фазы:

1. **Фаза 1: Селектор файлов (File Selector)**
   * Анализирует только структуру репозитория (дерево путей без чтения содержимого) + `README.md` + пользовательский контекст.
   * Отсекает лишнее (тесты, вендорные библиотеки, сгенерированный код, бинарники).
   * Формирует плоский список ключевых файлов с их категоризацией: `product`, `containers`, `components`, `external_systems`, `flows`.
2. **Фаза 2: Экстрактор архитектуры (Context Extractor)**
   * Загружает точечное содержимое файлов, отобранных на шаге 1.
   * Обогащает контекст единым корпоративным словарем тегов (`vocabulary.json`).
   * Извлекает семантику и генерирует валидированный **структурированный JSON-контракт**: границы продукта, внутренние компоненты, межсервисные связи, бизнес-сценарии (flow) и маркеры неопределенности (`uncertainties` / `#manual_check`).

---

### Этап 3. Детерминированная кодогенерация (JSON → LikeC4 DSL)
* **Преобразование:** генератор трансформирует JSON-контракт в валидные файлы спецификации LikeC4 (`.c4`).
* **Дедупликация связей:** общие инфраструктурные и платформенные сервисы (Kafka, SSO, общие БД) не дублируются заново, а маппятся на канонические идентификаторы из единого реестра (`shared/externals.c4`).
* **Построение вьюшек:** формируются статические представления (уровни C1, C2, C3) и динамические sequence-диаграммы бизнес-потоков.
* **Упаковка:** результат собирается в артефакт бандла (`bundle.json` + `.c4`-файлы + конфиг проекта).

---

### Этап 4. Публикация и изоляция (Multi-project Registry)
* Полученный бандл доставляется в целевой репозиторий архитектурного пространства (Output Repo).
* **Модель изоляции:** каждый продукт изолирован в собственной директории (`docs/c4/<project_slug>/`) со своим независимым файлом конфигурации, но доступен для включения в общую карту направления (`Landscape Map`).
* **Синхронизация:** определяется тип изменений для каждого файла (`create` или `update`), создается ветка, разрешаются конфликты (rebase) и выполняется слияние изменений в основную ветку (`master`).

---

### Этап 5. Сборка и деплой
* **Компиляция:** запускается CLI LikeC4 (`likec4 build`), который компилирует DSL-модель в SPA/статический сайт.
* **Деплой:** статический артефакт публикуется на веб-сервере документации (GitLab Pages / внутренний хостинг).
* **Результат:** пользователь получает прямую ссылку на готовую интерактивную диаграмму с навигацией по уровням вложенности (drill-down от Landscape до Component).

---

### Сопутствующий контур: Управление жизненным циклом (Day 2)
Пайплайн поддерживает обратную операцию — **выборочное удаление выгрузок**: опрашивает дерево проектов в репозиториях документации, генерирует атомарный коммит на удаление каталога сервиса из `docs/c4/` и пересобирает общий Landscape.
