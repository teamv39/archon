# Технологический стек Archon

> Статус: Принят командой с учетом перехода на **Managed SaaS (Context-as-a-Service)** по [ADR-0006](../adr/0006-saas-delivery-model-and-ai-native-source-of-truth.md).
> Язык основного бэкенда — **Kotlin / JVM**.

---

## 1. Главные принципы выбора технологий

1. **Cloud-Native SaaS First (Context-as-a-Service):** 
   В соответствии с [ADR-0006](../adr/0006-saas-delivery-model-and-ai-native-source-of-truth.md) система разворачивается и масштабируется в нашей управляемой облачной инфраструктуре. Подключение клиентов за 2 минуты через GitHub App / GitLab OAuth без необходимости настраивать базы данных и выделять серверы.
   * **Privacy-by-default:** Исходный код клонируется во временные изолированные контейнеры-песочницы только на время AST-разбора и немедленно удаляется. В постоянном хранилище сохраняются исключительно архитектурные метаданные и граф.
   * **Гибридный сканер для закрытых контуров:** (OQ-23) всё ещё не закрыт.
2. **Один язык на бэкенд — Kotlin / JVM:** Весь бэкенд пишем на Kotlin. Исключение — только LLM-модули на Python (см. п.3). Держать один основной стек критично при компактной команде.
3. **Python только там, где есть LLM:** Python оставляем исключительно для модулей семантического анализа, эмбеддингов и RAG (`interpret`, `drift`), где экосистема нейросетей не имеет равных.
4. **Готовые enterprise-компоненты вместо велосипедов:** Для очередей, графов, авторизации и оркестрации берем зрелые проверенные Open-Source решения с поддержкой multi-tenancy.
5. **Оптимизация потом:** GraalVM / native-image рассматриваем после готовности основного функционала как оптимизацию, а не как требование на старте.

## 2. Базовая инфраструктура и платформенные компоненты

Эти компоненты разворачиваются в нашем облачном кластере (Kubernetes):

| Слой / Задача | Технология | Почему именно она |
| :--- | :--- | :--- |
| **Граф знаний + Реляционные данные** | **PostgreSQL 16+ с расширением Apache AGE** | Multi-tenancy (изоляция организаций). Закрывает сразу две задачи: реляционные таблицы (аккаунты, подписки, настройки, аудит) и графовую модель (узлы архитектуры, связи, запросы openCypher) в единой СУБД. |
| **Векторная БД (RAG / Поиск)** | **Qdrant** | Быстрый векторный движок на Rust, эффективная фильтрация по метаданным и тенантам (tenant_id payload). |
| **Шина событий и кэш** | **NATS JetStream + Redis** | NATS — сверхлегкий event bus для передачи задач между воркерами. Redis — кэширование горячего графа и сессий. |
| **Оркестрация пайплайнов** | **Temporal.io** | Управление сложными и долгими распределенными процессами (фоновый анализ репозиториев, ретраи при сбоях LLM, шаги склейки). |
| **Протокол для AI-агентов** | **MCP (Model Context Protocol)** | JSON-RPC 2.0 поверх SSE / HTTP для прямой интеграции с Cursor, Copilot Workspace, Claude Desktop. |
| **Песочницы для анализа кода** | **Эфемерные контейнеры (gVisor / K8s)** | Изолированное клонирование и парсинг кода клиентов с гарантированным удалением после извлечения фактов. |
| **Политики архитектуры** | **Open Policy Agent (OPA / Rego)** | Индустриальный стандарт декларативных архитектурных инвариантов и проверок. |
| **Рендеринг C4-диаграмм** | **LikeC4 / React Flow** | Декларативное описание C4-архитектуры и рендеринг интерактивных масштабируемых схем в портале. |
| **SSO / Управление доступом** | **Keycloak / SaaS Auth Gateway** | GitHub/GitLab OAuth для привязки репо, корпоративный SSO (OIDC/SAML) и генерация scoped токенов для MCP. |
| **Хранилище секретов** | **HashiCorp Vault / Cloud KMS** | Безопасное хранение токенов интеграций GitHub App и ключей клиентов. |

## 3. Язык бэкенда: Kotlin / JVM (решение принято)

Развилку Go vs Kotlin закрываем в пользу **Kotlin / JVM** — это приоритет Паши и этого достаточно для всего ядра Archon.

### Почему Kotlin / JVM подходит

- Весь продукт общается через контракты (REST + события NATS + Temporal) — языку бэкенда всё равно, Spring это или что-то другое.
- **Temporal** имеет первоклассный Java/Kotlin SDK — для `runtime` это один из лучших вариантов.
- Keycloak, OPA, Qdrant, Apache AGE — работают поверх REST/SQL, от языка не зависят.

### Фреймворки — выбор сделан: Spring Boot 4

Для основного бэкенда (`archon-core-service`) утвержден стек:
- **Язык:** Kotlin 2.3.0
- **Фреймворк:** Spring Boot 4.1.0
- **Рантайм:** JDK 21 (LTS)
- **Сборка:** Gradle (Kotlin DSL), модуль `archon-core-service/archon-core/build.gradle.kts`

### GraalVM — после MVP

GraalVM / native-image пробуем **после готовности основного функционала**, как оптимизацию сервисов (быстрый старт, меньше памяти в K8s). На старте не блокируемся на нём.

### Про Go

Go из основного стека убираем. Допуск только как исключение: **1–2 отдельных сервиса на Go, если будет срочная необходимость** («горит — надо быстро выкатить»). Это не часть базового стека и не требует держать Go как второй язык для всего бэкенда.

## 4. Стек по 17 модулям системы

### Блок «Витрина» (Showcase)
* **`portal` (Веб-портал):**
  * **Стек:** TypeScript, React, Next.js / Vite, Tailwind CSS, shadcn/ui.
  * **Библиотеки:** `@likec4/core` / `@likec4/diagrams` (интерактивные графы C4), TanStack Query (кэш данных), TanStack Table.
  * **Функционал:** Интерактивные C4-диаграммы, Spec-Drift Monitor, Knowledge Graph Explorer, Assurance Inbox.
* **`mcp-server` (Шлюз контекста для AI-агентов):**
  * **Стек:** Kotlin (или TypeScript / Python с официальным MCP SDK).
  * **Протокол:** Model Context Protocol (JSON-RPC 2.0 поверх SSE / HTTP). Отдача нормализованных контрактов, топологии и архитектурных инвариантов агентам в Cursor, Copilot, Claude Desktop.
* **`pr-bot` и Docs-as-Code Engine (Git Sync):**
  * **Стек:** Kotlin 2.3.0 (Spring Boot 4.1.0).
  * **Интеграции:** GitHub App / GitLab Webhooks & REST/GraphQL API. Автоматическое создание PR с обновлением `AGENTS.md` и `.archon/` каталогов, проверка архитектурных инвариантов при мерже.
* **`chat-bot` (Бот в мессенджерах):**
  * **Стек:** Kotlin (или Python-микросервис рядом с LLM, если удобнее для RAG).
  * **Интеграции:** Slack Bolt SDK, Mattermost API, Telegram Bot API.
* **`export` (Экспорт отчетов и артефактов):**
  * **Стек:** Kotlin / Node.js.
  * **Библиотеки:** Puppeteer / Playwright (генерация PDF из HTML/C4), генераторы Structurizr DSL / JSON / Markdown.

### Блок «Решение» (Decision)
* **`assurance` (Жизненный цикл находок и рисков):**
  * **Стек:** Kotlin.
  * **Хранилище:** PostgreSQL (реляционная модель статусов, аудит-лог действий архитекторов, вердикты).

### Блок «Мозг» (Brain)
* **`model` (Хранилище графа знаний):**
  * **Стек:** Kotlin.
  * **Движок:** PostgreSQL + Apache AGE (доступ через SQL + openCypher с multi-tenant изоляцией), Apache Arrow/Memory для быстрой сборки графов.
* **`resolve` (Склейка сущностей между репо):**
  * **Стек:** Kotlin.
  * **Алгоритмы:** Графовые алгоритмы сопоставления контрактов, нечеткий поиск (`fuzzy matching`), нормализация эндпоинтов и топиков.
* **`policies` (Архитектурные политики):**
  * **Стек:** Kotlin + OPA.
  * **Библиотеки:** Open Policy Agent (in-process evaluation через OPA REST / sidecar).
* **`drift` (Детектор расхождений доков и кода):**
  * **Стек:** Python (FastAPI / Celery воркер).
  * **Библиотеки:** LlamaIndex / LangChain, sentence-transformers, интеграция с локальными LLM (vLLM / Ollama / OpenAI-compatible).

### Блок «Фабрика» (Factory)
* **`registry` (Реестр сервисов, словарь, конфигурация):**
  * **Стек:** Kotlin.
  * **Хранилище:** PostgreSQL + кэш в памяти.
* **`sources` (Коннекторы к источникам):**
  * **Стек:** Kotlin.
  * **Инфраструктура:** Прием вебхуков коммитов/PR от GitHub/GitLab, безопасное клонирование во временные контейнеры-песочницы (gVisor/K8s), работа с токенами через HashiCorp Vault.
* **`extract` (Детерминированный парсер кода):**
  * **Стек:** Kotlin. Для мультиязычного парсинга (Tree-sitter) — при необходимости выносим Tree-sitter в маленький sidecar (Rust/Python/Go) за gRPC/HTTP, ядро остаётся на Kotlin.
  * **Перспектива (OQ-23):** База для компиляции легковесного CLI-сканера (`archon-scanner`) для разбора кода в закрытых корпоративных контурах.
  * **Библиотеки:** JavaParser / Kotlin PSI / ANTLR для JVM-языков; Tree-sitter, OpenAPI parser, YAML/JSON Schema validators.
* **`interpret` (Семантический анализатор документации):**
  * **Стек:** Python.
  * **Библиотеки:** Unstructured.io (парсинг markdown/docx/pdf), LlamaIndex (RAG), Pydantic (валидация JSON-схем ответов LLM).
* **`reconcile` (Разрешение конфликтов фактов):**
  * **Стек:** Kotlin.
  * **Логика:** Матрица доверия источникам (AST факт > LLM предположение), слияние свойств в канонический Extraction Contract.

### Блок «Фундамент» (Foundation)
* **`runtime` (Оркестрация и бюджеты):**
  * **Стек:** Temporal.io Server + Kotlin SDK для воркеров, Prometheus/OpenTelemetry для сбора метрик затрат токенов и очередей задач.
* **`platform` (Аудит, права, безопасность, multi-tenancy):**
  * **Стек:** Kotlin + Keycloak (OIDC/SAML) / SaaS Auth Gateway, Casbin (RBAC/ABAC), HashiCorp Vault.
  * **Функционал:** Мультитенантность (изоляция организаций), биллинг, квотирование токенов LLM, аудит и контроль доступа к MCP Server (OQ-24).
