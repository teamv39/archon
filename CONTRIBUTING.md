# Contributing

Гайд для участников проекта.

## Как начать

1. Клонируй репозиторий
2. Прочитай `/docs/README.md` для понимания структуры документации
3. Прочитай `/docs/DEVELOPMENT.md` для понимания workflow
4. Найди задачу в GitHub Projects или создай новую

## Процесс работы

### 1. Создание задачи

Создай issue в GitHub Projects с:
- Понятным описанием
- Лейблами (`feature`, `bug`, `research`, `documentation`)
- Линком на Epic если задача часть большой фичи

### 2. Создание ветки

```bash
git checkout develop
git pull
git checkout -b feature/ARCH-123-short-description
```

### 3. Разработка

- Пиши код
- Пиши тесты
- Обновляй документацию в том же PR
- Делай атомарные коммиты с понятными сообщениями

### 4. Pull Request

Создай PR в `develop`:
- Используй шаблон описания из `/docs/DEVELOPMENT.md`
- Проставь reviewers
- Убедись что CI checks passed

### 5. Code Review

- Отвечай на комментарии
- Исправляй замечания
- Resolve conversations после исправлений

### 6. Merge

После approval и прохождения всех checks — мерж в `develop`.

## Документация

**Важно:** Изменения в коде = изменения в документации.

### Когда обновлять документацию

- Добавил новый модуль → обновил `/docs/architecture/`
- Принял архитектурное решение → создал ADR
- Изменил API → обновил спеку в `/docs/api/`
- Провел исследование → зафиксировал результаты в `/docs/research/`

### Как писать документацию

- Markdown формат
- Без эмодзи
- Технический стиль, без пафоса
- Конкретика > общие слова
- Code examples где нужно

## Architecture Decision Records

Создавай ADR когда:
- Выбираешь между технологиями
- Меняешь архитектурный подход
- Принимаешь решение с долгосрочными последствиями

Используй шаблон `/docs/adr/TEMPLATE.md`

## Code Style

- Следуй language-specific best practices
- Используй линтеры и форматтеры
- Код должен быть понятен без комментариев
- Комментируй только неочевидные вещи

## Testing

- Unit tests для core logic
- Integration tests для интеграций
- Performance tests для критичных компонентов
- Coverage target: 80%+

## Коммуникация

- Все технические обсуждения в GitHub issues/PR
- Синхронизация в Slack/meetings
- Важные решения фиксируем в ADR

## Вопросы?

- Читай `/docs/` — там ответы на большинство вопросов
- Не нашел ответ? Создай issue с вопросом
- Нашел ответ? Обнови документацию чтобы следующий человек его тоже нашел
